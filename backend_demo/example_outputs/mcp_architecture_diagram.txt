Model Context Protocol (MCP) Architecture Diagram
=================================================

Below is a Mermaid diagram summarizing the MCP architecture:

```mermaid
graph TD
    %% LLM Interaction
    LLM[Large Language Model] <-->|Context & Tools| Host[MCP Host Application]

    %% Host Internals
    subgraph "Host Application (e.g., Claude Desktop, VS Code)"
        Host <--> Client[MCP Client]
    end

    %% Transport Layer
    Client <-->|JSON-RPC 2.0| Transport[Transport Layer]
    
    subgraph "Transport Mechanisms"
        Transport --- Stdio[Stdio Transport<br/>Local Process]
        Transport --- SSE[HTTP + SSE Transport<br/>Remote Server]
    end

    %% Server Side
    Transport <-->|JSON-RPC 2.0| Server[MCP Server]

    subgraph "MCP Server Components"
        Server --- Resources[Resources<br/>Data/Files]
        Server --- Tools[Tools<br/>Executable Functions]
        Server --- Prompts[Prompts<br/>Interaction Templates]
    end

    %% External Data
    Resources <--> Data[External Data Sources]
    Tools <--> API[External APIs / Systems]

    %% Styling
    style Host fill:#f9f,stroke:#333,stroke-width:2px
    style Server fill:#bbf,stroke:#333,stroke-width:2px
    style LLM fill:#dfd,stroke:#333,stroke-width:2px
```

Summary of Connections:
1. LLM: Provides the intelligence, receives context from the Host, and requests tool execution.
2. Host: The container application that manages the LLM and the MCP Clients.
3. MCP Client: Handles the protocol logic within the host.
4. Transport Layer: The bridge (Stdio or SSE) that carries JSON-RPC messages.
5. MCP Server: Exposes capabilities (Resources, Tools, Prompts) to the Client.
6. Data/APIs: The actual backend systems the MCP Server interacts with.
